# 컷·실기 편집 저장 복구 (2026-09-06)

## 사용자 동작

- 정시컷 편집: 지점 수능컷 또는 총점컷 하나만 바꿔도 저장한다.
  수정하지 않은 값은 저장 직전에 다시 조회하여 보존한다.
  본원 관리자 맥스컷·과거컷에도 동일하게 적용한다.
- 실기 에디터: 본원 관리자는 종목명·기록·배점을 표에서 수정한 뒤
  `수정사항 저장`을 누른다. 종목명은 해당 종목의 남녀 행에 함께 적용한다.
- 두 화면 모두 저장 후 새 조회 결과가 일치해야 성공으로 표시한다.
  실패하면 수정값을 유지한다. 실기 수정은 기존 행 ID를 사용하며 추가·삭제하지 않는다.
- 기존 실기 신규 추가·대량 추가·삭제 기능은 유지한다.

## 원인과 계약

컷 저장기는 지점 2개, 관리자 4개 점수 필드를 모두 요구한다. 이전 화면은
변경 필드만 전송하여 서버가 행을 건너뛰어도 성공으로 표시했다.
실기 화면은 읽기 전용 표만 렌더링하고 기존 수정 API를 연결하지 않았다.

기존 인증·관리자 정책과 서버 코드는 변경하지 않는다.
실기 수정은 `/jungsi/admin/practical-table/bulk-update`에
`{U_ID, year, updates, additions: [], deletions: []}`를 전송한다.
수정 대상은 선택 학교·학년도의 최신 조회에 존재하는 ID로 제한한다.
운영 API와 같은 자료형·Authorization 헤더를 브라우저 테스트에서 검증한다.

## 검증

단일 컷 저장·재조회, 다른 필드 보존, 잘못된 성공 응답, 저장 중 새 입력,
실기 이름/기록/배점 수정, 남녀 행 보존, 관리자 권한, 학교 이동 확인,
모바일 편집, 네트워크/서버 실패의 평이한 한국어 안내를 검증한다.

운영 서버에서 읽은 실제 저장 함수는 모의 DB로 계약을 검증하고, 운영 CORS
사전 요청도 점검한다. 브라우저 저장 테스트는 격리된 시험 데이터로 진행하며
실제 사용자 데이터 저장을 수행했다고 주장하지 않는다.
