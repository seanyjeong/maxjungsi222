# 모형별 최고표점·한체대 미응시 수정 (2026-09-08)

2026-09-08 사용자 승인(“응 반영해줘”)에 따라 운영 계산 모듈에 반영했다. 이 변경에는 선택한 모형 전달과 미응시 결과 표시를 위한 프론트 수정이 포함된다.

## 바뀌는 계산

- 개인상담과 통합 계산기는 선택한 학년도와 모형을 `basis_exam`으로 전송한다. 기존 `/jungsi/calculate`가 해당 `정시최고표점` 자료를 읽는다. 기본비율·특수공식 모두 같은 요청 경로를 쓴다.
- 최고표점 설정은 2027학년도 35개 모집단위에서 확인됐다. 특수공식에 최고표점 분모를 직접 쓰는 고려대 사배자·충북대·숭실대 3개도 포함해 대상은 38개다. 한체대 22개 및 고려대, 한양대, 서울과기대, 서울시립대, 숙명여대, 이화여대, 인하대, 경상국립대, 충북대, 숭실대의 해당 모집단위다.
- 수능 고정 화면인 최종지원·디버거는 기존 동작을 유지한다. 컨설팅 허브는 모형별 저장 상담을 표시하는 구조이며 자체 환산을 하지 않는다.
- 시험·학생을 바꾸면 이전 상담을 비우고, 이전 요청이 늦게 끝나도 카드·점수·저장에 반영하지 않는다. 계산 실패를 0점으로 저장하지 않고 한국어로 안내한다. 상담 복원은 모든 수능 계산이 끝난 뒤 카드를 만든다.
- 한체대 2027 실기 21개 모집단위는 미응시 종목을 0점으로 반영한다. 전 종목 미응시는 실기 0점과 ‘전 종목 미응시 · 불합격 대상’을 표시한다. 빈칸은 기록 입력 대기이며 미응시로 간주하지 않는다.
- F·파울 등 기존 채점, 다른 대학·2026학년도 미응시 정책, 특수체육 면접은 유지한다. 실기 입력창의 결시 입력값은 기존에 지원하던 `미응시`다.

한체대 근거: [2027 정시 모집요강 공지](https://ipsi.knsu.ac.kr/ipsi/regular/application.do?articleNo=56194&mode=view)의 책자 44쪽(파일 46쪽). 기존 검수의 공식 원문·직접 확인한 표를 재사용했다.

## 예시와 검증

검증용 가상 성적(화작 표준120, 확통100, 영어3, 생윤60, 사문65)의 사회체육학과 수능 환산은 3월 555.65, 6월 600.75, 9월 574.78, 수능 571.54다. 모형별로 현재 등록된 최고표점 값을 사용한다. 최고표점 원자료 자체를 새로 확정·갱신한 작업은 아니다.

실기 남학생 기록 `미응시 / 284 / 12.4`는 166.67점, 같은 기록에서 미응시 대신 F는 208.33점이다. 세 종목 미응시는 0점이다.

- 최고표점 대상 2026·2027 학년도/모형 실제 라우터 190건, 최고표점 비사용 기본비율 114개 학과의 모형별 점수 보존.
- 한체대 21개 전형 × 남녀 × 미응시 7조합 = 294건 독립 산수 일치. 기존 기록·타 대학·2026 정책 보존 4,144건.
- 운영 Node 18에서 후보 코드를 메모리로 실행한 336건 일치. 설치 후 실제 운영 모듈 336건도 통과했다.
- 신규/관련 Playwright 63개, 관련 Node 15개, 신규 backend Node 5개 통과. 최초 전년도 결과 테스트 1건은 응답 도착 전 즉시 확인하는 시점 문제였으며 파일 변경 없이 재실행 및 최종 전체 실행에서 통과했다.
- Puppeteer에서 배포 후보 프론트 → 운영 수능 API로 38개 학과 × 4모형 = 152건 검증. 실제 인증 헤더·CORS·응답 타입 확인. 실기는 후보 라우터를 연결해 미응시·F·빈칸 표시와 화면 캡처를 확인했다. 분리된 배포 후보의 화면·저장 smoke 11개도 통과했다.
- 학생 데이터 조회·수정은 차단하고 가상 성적만 사용했다. 저장 검증은 가상 API 요청 검사다.
- 별도 프론트 빌드·TypeScript·lint 설정이 없는 정적 JS 프로젝트다. 변경 JS 문법 검사, 계약·브라우저 검사로 검증한다. DB·환경 변경이 없어 마이그레이션 검사는 해당 없다.

## 배포 순서 및 복원

대상은 Vultr `/root/supermax`의 `jungsi` 서비스와 `seanyjeong/maxjungsi222` main/Pages다. 현재 서비스 active, Node v18.19.1, remote main은 위 기준 SHA와 일치했다.

1. 운영 세 파일 및 의존 모듈 SHA를 `before-sources.json`/`verification.json`과 대조하고, 새 두 파일이 없는지 재확인한다. main 변경 여부도 확인한다.
2. 전용 백업 `/root/backups/et-exam-20260908-xm5ddZ`가 없음을 확인한 후 만들고 기존 `silgi-calculator.js`를 `cp -a`로 보관한다. `release/` 세 파일을 백업의 `release/` 아래 상대 경로대로 SCP 전송한다. `node --check` 세 파일을 실행한다.
3. `ssh vultr 'systemctl stop jungsi'` 후 해당 세 파일만 `/root/supermax/`에 설치하고 `ssh vultr 'systemctl start jungsi && systemctl is-active jungsi'`로 확인한다. 계산 smoke 실패 시 즉시 복원한다.
4. 운영 `/silgi/calculate`에 위 가상 사례를 보내 166.67·208.33·0.00 및 미응시 상태를 확인한다. 수능 API의 9월 574.78도 확인한다.
5. 분리 프론트 작업 트리에서 manifest의 화면·회귀 테스트·문서 12개 파일만 `git add` 후 커밋한다. 최신 main 일치 확인 후 `git push origin HEAD:main`을 실행하고 Pages 성공·공개 파일 SHA·브라우저 smoke를 확인한다.

운영 복원 명령은 `ssh vultr 'python3 /root/backups/et-exam-20260908-xm5ddZ/deploy_remote.py /root/backups/et-exam-20260908-xm5ddZ rollback'`이다. 서비스 프로세스·포트 종료와 파일 SHA를 확인한 뒤 원본을 복원하며 추가 파일은 전용 백업의 `withdrawn/`으로 이동한다. GitHub는 새 배포 커밋만 `git revert <배포SHA>` 후 정상 push한다. 기존 작업이나 다른 커밋을 강제 덮어쓰지 않는다.
