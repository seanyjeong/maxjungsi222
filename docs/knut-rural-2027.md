# 한국교통대학교 2027 정시 농어촌 모집단위 추가

## 현재 상태와 범위

2026-10-14, `isaac/sub1-교통대농어촌`의 `0f50d1c`에서 데이터 정의·적용 도구·검증을 준비했다.
이후 소유자가 운영 `main` 병합·배포·정시 DB의 두 모집단위 추가를 명시적으로 승인했다.
통합은 원래 작업 폴더를 보존하고 별도 worktree에서 진행한다. 이 문서의 적용 절차에 따라
백업·미리보기·충돌 검사를 마친 뒤 실행하며, 실제 배정 ID와 결과는 운영 반영 기록에 남긴다.

| 모집단위 | 전형 | 군 | 수능 | 학생부교과 | 실기 | 실기 복제 원본 |
| --- | --- | --- | --- | --- | --- | --- |
| 스포츠의학과 | 학생부교과(농어촌) | 가 | 0% | 60% | 40% | U_ID 39 / 2027 |
| 스포츠산업학과 | 실기/실적(농어촌) | 가 | 0% | 30% | 70% | U_ID 38 / 2027 |

- 모집정원: SQL `NULL`. 수시 미충원 이월인원이 있을 때만 모집하며 원서 접수 전 발표한다.
- 수능최저: 없음. 수능 영역비율·한국사 필수응시·영어 환산표·선택/가산 규칙은 복사하지 않는다.
- 지원자격: 농어촌 6년 또는 12년 과정. 특목고·체육고 지원 불가.
- 실기: 20m왕복달리기·윗몸일으키기·제자리멀리뛰기, 각 모집단위 156행(3종목 × 남녀 × 26급간).
- 기존 일반전형의 경쟁률, 과거 정원, 컷, 상담/지원 기록을 복사하지 않는다.
- 학생부는 기존 상담 화면의 **교사가 환산점수를 직접 입력하는 방식**을 따른다.
  학생부 자동 환산식이나 지원자격 자동 판정은 이번 작업에 포함하지 않는다.

## 확인한 데이터 추가 방식

현재 실행 중인 `jungsi.service`의 작업 경로와 DB 스키마를 읽기 전용으로 확인했다.
이 저장소에는 모집단위 seed나 전용 생성 API가 없고 다음 MySQL 세 테이블을 조인한다.

1. `정시기본`: `(U_ID, 학년도)` 복합 기본키. 대학·학과명, 모집정원, 표시용 종목, 태그.
2. `정시반영비율`: 같은 U_ID/학년도로 연결. 수능·내신·실기 비율 및 계산 설정.
3. `정시실기배점`: 같은 U_ID/학년도로 연결. 성별·종목별 기록과 배점.

`schools`, `cutoffs`, `filter-data`, `school-details` 및 `formula-details`가 이 구조를 이용한다.
새 학과명에 전형명을 붙여 일반전형과 구분하며, 목록 태그로 농어촌·수시 이월 조건·수능최저 없음을 표시한다.
지원자격·인원 미정 사유·출처는 `기타설정.admissions`에도 보관한다.
기존 프론트/API/계산기 코드를 수정하지 않는다. 학교 로고는 원본의 `logo_url`을 재사용한다.

조회 당시 최대 U_ID는 204였다. **205/206은 테스트용 예시이며 운영 배정이 아니다.**
다른 창의 추가 작업과 충돌하지 않도록 통합 담당자가 적용 직전에 두 새 U_ID를 지정해야 한다.
기존 모든 학년도와 세 테이블의 고아행까지 충돌 검사하며, 동일 대학 농어촌 전형이 이미 있으면 중단한다.

## 적용 담당자용 절차

기존 `mysql2/promise`를 사용할 수 있는 Node 환경이 필요하다. 의존성을 설치해야 한다면
상위 패키지를 건드리지 않도록 반드시 작업 사본의 절대 경로를 `npm --prefix`로 지정한다.
연결은 환경변수 `KNUT_DB_URL`로만 전달한다. 운영 연결을 자동으로 찾거나 서버 코드에서 비밀번호를 읽지 않는다.

```sh
# 순서: 스포츠의학과 새 U_ID, 스포츠산업학과 새 U_ID
# 아래 숫자는 예시. 적용 담당자가 충돌을 확인하여 결정한다.
node scripts/add-knut-rural-2027.js --ids=205,206
```

기본 실행은 SELECT만 수행하며 JSON 계획을 출력한다. 잠금·트랜잭션·DB 쓰기를 하지 않는다.
대상 DB/학년도·새 U_ID·출처와 원본 변경 여부·추가될 316행을 사용자에게 보고하고,
운영 적용 범위를 확인한 뒤 기존 절차에 따라 대상 테이블을 백업한다.
그 이후에만 같은 명령에 `--apply`를 붙인다.

적용은 InnoDB 확인 → 전용 잠금 → 트랜잭션 → 원본/중복 재검사 → 기본 2행·비율 2행·실기 312행 삽입
→ 행 수 검증 → 커밋 순서다. 오류 시 전체 롤백한다. DDL·UPDATE·DELETE는 없다.
재실행은 기존 전형을 변경하지 않고 중단한다. 성공 후 새 U_ID를 기록하고 목록/상세/상담 화면을 다시 확인한다.

## 검증

- 최종 결과: Node 전체 45개 통과(skip 0), Playwright 1개 통과, JS 문법·diff 검사 통과.
- Node 단위 및 격리 MySQL 통합검증: 비율 전환, NULL 정원, 수능 규칙 제거, 원본 배점의 정확한 복제,
  조회 전용 미리보기, 두 번째 모집단위 삽입 도중 실패 시 전체 롤백, 중복 방지, 기존 38/39번 보존.
- 기존 대학정보 화면의 Playwright 검증: 두 전형 표시, 0/60/40 및 0/30/70 비율,
  모집인원 `—`, 남녀 실기표 3종목, 한국사 필수응시 표시 없음. 외부 API는 가로채고 테스트 데이터만 제공했다.
- 운영 계산 모듈에 메모리상의 가상 새 U_ID 데이터를 전달: 수능 미입력 0점,
  남녀 실기 만점 스포츠의학 400점·스포츠산업 700점. DB 연결/쓰기 없이 실행했다.
  결과는 `docs/sources/knut-rural-2027/calculator-verification.json`에 보존했다.
- 별도의 TypeScript/ESLint 설정은 없는 저장소다. 변경 JS 문법과 diff 공백 검사를 수행한다.

재현 예시(운영 DB 사용 금지):

```sh
# 격리 MySQL 8의 loopback 주소와 knut_rural_test 스키마만 테스트가 허용한다.
# KNUT_TEST_DB_URL을 해당 테스트 컨테이너의 연결 문자열로 설정한다.
node --test tests/knut_rural_2027.test.js
PYTHONDONTWRITEBYTECODE=1 python3 -m pytest -q -p no:cacheprovider \
  --basetemp=node_modules/knut-pytest-tmp tests/test_knut_rural_2027_playwright.py
node --check scripts/add-knut-rural-2027.js
node --check scripts/knut-rural-plan.js
git diff --check
```

테스트 DB 환경변수가 없으면 MySQL 통합검증은 skip하므로 실제 검증 시 반드시 지정한다.
운영 전체 E2E나 신규 데이터 배포가 완료된 것으로 해석하지 않는다.

검증 의존성 설치 중 npm이 상위 `/Users/etlab/node_modules`를 선택한 실수가 있었다.
상위 package.json/lockfile은 변경하지 않았고, `npm ci --ignore-scripts`로 잠금파일 기준 복구했다.
그 후 작업 사본 안에 `--prefix`를 지정해 설치했다. 기존 상위 설치 디렉터리의 바이트 단위 복원은 확인하지 못했다.
