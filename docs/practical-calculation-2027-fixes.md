# 2027 실기 점수 불일치 수정 — 2026-09-07

운영 DB와 계산 코드는 소유자 승인 후 2026-09-07 반영했다. 이 커밋에는 검증된 계산기·개인상담 프론트를 포함한다.

배포 검증: 실제 MySQL 임시 표의 적용/복원 성공, 배포 실패/복구 검사 13개 통과, 설치된 계산 경로 272건 통과. 운영 3개 표 전체가 승인 후보와 일치하며 비대상·2026 데이터는 보존했다. 지점컷·실기 편집기·9월 성적·맥스 전체 합격자 조회의 기존 GitHub 변경을 유지했다. 별도 미배포 상담멘트 기능과 다른 로컬 변경은 포함하지 않았다.

아래는 배포 대상으로 확정한 수정안과 최초 검산 근거다. 보류·추가 확인 40개는 그대로 유지한다.

## 입력·화면 계약

- 기본 실기 계산에서 확인된 필수 종목을 누락해도 분모를 줄이지 않는다. 한체대 1종목 만점 입력이 실기 전체 만점으로 부풀지 않는다.
- 화면은 필수 기록이 모두 입력되기 전 합산을 보류한다. 일반/우천 대체 종목과 성별 체조 종목을 구분한다.
- 계산 실패·빈 응답·NaN을 0점으로 표시하지 않고 한국어 안내를 표시한다.
- 늦은 응답은 새 입력을 덮어쓰지 않는다. 상담 카드의 계산 대기/실패 상태에서는 자동 저장도 대기하고 상태를 안내한다. 기록을 모두 입력해 정상 계산되면 저장된다.
- 편집기에서 종목명이 바뀌어 원문 종목 구성과 달라진 표에는 오래된 종목명을 강제하지 않는다.
- 기존 `/silgi/calculate` 경로·인증·응답 객체 형태를 유지한다. 반올림 규정에 따라 `result.totalScore` 문자열의 소수 자리 수만 달라질 수 있다.
- 2026 계산과 결시/F/G/미응시/파울/실격 **처리 정책**은 유지한다. 배점표·전형 만점 수정에 따른 점수 변화와 정책 변경은 구분한다.

500줄 제한을 지키기 위해 계산기 로직은 `calculator/`, 개인상담 로직·스타일은 `counsel/`로 분리했다. 기존 개인상담 선언 함수와 CSS는 분리 단계에서 원문 동일성을 검사했다. 공통 페이지 자산과 다른 화면의 기존 수정은 되돌리지 않았다.

## 운영 반영 승인 단위

1. 새 승인 후 GitHub 프론트의 현재 버전과 로컬 선행 변경을 다시 대조한다. 이번 작업 외 변경·삭제는 자동으로 포함하지 않는다.
2. Vultr `/root/supermax`의 실기 관련 파일과 대상 DB를 별도 백업한다. 현재 소스 SHA·행별 이전 값이 후보와 다르면 적용을 중단한다.
3. 짧은 점검 구간에서 서비스를 정지하고 승인된 `apply.sql`과 `release/` 파일 5개를 같은 묶음으로 반영한다. `mysql --force`는 사용하지 않는다.
4. 서비스 재시작 후 대상/비대상/2026 행과 코드 SHA를 확인하고 실기·수능·상담 저장 스모크를 수행한다.
5. 실패 시 같은 서비스 정지 구간에서 `rollback.sql`을 실행하고 백업한 실기 파일을 복원한다. 백업에 없던 신규 모듈은 이번 배포분만 제거한 뒤 서비스 확인한다.
6. 프론트 승인 파일만 GitHub Pages에 반영하고 새 브라우저에서 로드된 파일 SHA와 사용자 경로를 재확인한다.

운영 적용과 실제 임시 표 적용/복구 리허설은 완료했다. 실제 학생 계정의 브라우저 세션은 Aside 프로필 미연결로 사용하지 않았다. 공개 화면 검증에서는 가상 학생으로 요청/저장 형식을 확인하며 실제 학생 데이터를 수정하지 않는다. 수동 복구 시에는 배포 영수증의 전용 백업과 행 값 검증이 포함된 복원 명령을 사용한다.
